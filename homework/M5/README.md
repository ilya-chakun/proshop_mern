# M5: n8n Agentic Workflows

## Overview

Two n8n workflows integrating M3 (MCP server) + M4 (Feature Dashboard) + M5 (AI Agent):

- **WF1 — Manual Trigger**: Dashboard buttons → n8n webhook → AI Agent → MCP → UI update
- **WF2 — Scheduled Monitor**: Cron reads logs.json → AI Agent auto-toggles features → Telegram alerts

## Architecture

```
┌─────────────────┐    POST /feature-control    ┌──────────────────────┐
│  Feature         │ ──────────────────────────▶ │  n8n WF1             │
│  Dashboard       │ ◀────── JSON response ───── │  Webhook → Switch    │
│  (React, M4)     │                             │  → AI Agent → MCP    │
└─────────────────┘                             └──────────────────────┘

┌─────────────────┐    append events             ┌──────────────────────┐
│  simulate_wf2.py │ ──────────────────────────▶ │  logs.json           │
│  (sine error     │                             └──────────┬───────────┘
│   rate)          │                                        │ read
└─────────────────┘                             ┌──────────▼───────────┐
                                                │  n8n WF2             │
                                                │  Cron → Analyze →    │
                      ┌─────────────────┐       │  Switch → AI Agent   │
                      │  Telegram Bot    │ ◀──── │  → Telegram          │
                      └─────────────────┘       └──────────────────────┘
```

## Setup

### Prerequisites

- Docker + docker-compose (n8n runs in container)
- MCP server from M3 running on host (`ai/mcp-feature-flags/server.py`)
- Feature Dashboard from M4 running
- Python 3.10+ with `requests` package

### Steps

1. Start n8n:
   ```bash
   docker compose up -d n8n
   ```

2. Open http://localhost:5678, create account

3. Import workflows:
   - `workflows/wf1-manual-trigger.json`
   - `workflows/wf2-scheduled-monitor.json`

4. Configure credentials in n8n UI:
   - **Header Auth**: name=`n8n-feature-control-api-key`, header=`X-API-Key`, value from `frontend/.env`
   - **Chat Model**: your LLM API key (Anthropic/OpenAI/Gemini)
   - **Telegram API**: bot token from @BotFather

5. Connect sub-nodes to AI Agent in both workflows (Chat Model, MCP Tool, etc.)

6. Activate both workflows

## Hallucination Test (Algorithm-before-AI)

POST with `traffic_percentage: -50` is rejected **before** reaching the AI Agent:

**Layer 1 — Switch node (n8n):** Rule checks `traffic_percentage < 0 || > 100` → returns 400.

**Layer 2 — MCP server (Python):** `0 <= percentage <= 100` validation on line 178 of `server.py`.

> Constraint in code is law. Constraint in prompt is recommendation.

```bash
curl -X POST http://localhost:5678/webhook/feature-control \
  -H "Content-Type: application/json" \
  -H "X-API-Key: <key>" \
  -d '{"feature_id":"search_v2","action":"rollout","traffic_percentage":-50}'
# → 400 {"success":false,"rejected_at":"input-validation"}
```

## Security Note

In this homework, `X-API-Key` is stored in frontend `.env` for simplicity. In production, the frontend should call its own backend, which then makes authenticated requests to n8n. The API key should never be exposed in client-side code.

## GCAO Prompts

Both workflows use GCAO (Goal / Context / Action / Output) system prompts:

- **WF1**: Full action routing (check/test/rollback/rollout) with verification steps
- **WF2**: Execute upstream decision (deactivate/reenable) with Telegram alerting

## Tech Decisions

| Decision | Choice | Why |
|----------|--------|-----|
| n8n hosting | Self-host Docker | Need filesystem for logs.json + existing docker-compose |
| Frontend env vars | `REACT_APP_*` | Project uses react-scripts 3.4.3 |
| Logs storage | JSON file | Simplest option, volume mount into n8n container |
| MCP connection | host.docker.internal | MCP server runs on host, n8n in Docker |
| WF2 Memory | None | Cron is stateless — no conversation context needed |

## Что было сложно

1. **n8n task runner sandbox** — Code nodes в n8n 2.21.7 работают в изолированном sandbox без доступа к filesystem и `fetch()`. Пришлось читать logs.json через HTTP-запрос к backend API (`/api/feature-flags/logs`) вместо `fs.readFileSync()`.
2. **Gemini rate limits** — начинали с Google Gemini (free tier), быстро упёрлись в 15 RPM. Мигрировали на Anthropic Claude `claude-haiku-4-5-20251001` — всё заработало стабильно.
3. **Cross-node references в n8n** — `$json` в Switch/Code nodes не видит данные из других nodes. Нужен обязательный Merge Data Code node с паттерном `$('NodeName').first().json.field`.
